# Snakemake profile for PBS Pro

Source: Most of these scripts were originally authored by Derrick Lin, which in turn was heavily based on a PBS profile on GitHub (can't find link).

NB: None of the profiles on [Snakemake-Profiles](https://github.com/Snakemake-Profiles) worked out of the box, and development appears to have stalled there.

## Overview

This profile enables snakemake rules to be submitted as jobs to the PBS Pro job scheduler. 
The profile then monitors these jobs and reports their exit status back to snakemake.

#### `config.yaml`

This is the starting point for the Snakemake profile.
The config defined here is read when `--profile workflow/profiles/pbspro` is specified with the `snakemake` command.

The options here can be broadly divided into two blocks:
1. settings for interacting with PBS Pro
2. standard Snakemake options that could otherwise be specified from the command line

This YAML file can be ported to other workflows without modification.

##### Settings for interacting with PBS Pro
- `cluster`: This script is used to submit jobs to the PBS Pro job scheduler
- `cluster-status`: This script checks the status of running/completed jobs 
- `cluster-cancel`: This script is called when the snakemake workflow is canceled (such as with Ctrl-C)
- `cluster-config`: YAML file defining resource requests

##### Standard Snakemake options

Consult the official Snakemake docs.

#### `cluster.yaml`

This YAML file defines the `__default__` and rule-specific resource requirements for submitting jobs to the PBS Pro job scheduler.
The keys used here are mapping to PBS Pro resource specifications by way of `key_mapping.yaml`.

The `__default__` options apply to all rules, unless over-ridden.
These options include account (NCI project) information and storage volume requirements.

:warning: The log directory specified here must exist or else PBS Pro will not be able to write job logs upon completion, which will result in a slew of emails from the job scheduler.

#### `key_mapping.yaml`

This YAML file maps PBS Pro job resource specifications to a more human-friendly format.
This key-mapping approach is a step towards platform-independent profiles, where only the mapping files differ.

The values in this mapping file are read by `pbs_submit.py`.

This YAML file can be ported to other workflows without modification.

#### `pbs_submit.py`

This script is specified for the `cluster` option in `config.yaml`, and receives the jobscript as a parameter. 
Jobscripts are generated by Snakemake based on a rule and its inputs and outputs, etc. 
The script reads the resource requirements from `cluster.yaml` and converts these to PBS Pro resource specification format based on `key_mapping.yaml`, and then returns the job id.

This script was authored by Derrick Lin, heavily based on a script on GitHub that I cannot now locate.

This script can be ported to other workflows without modification.

#### `pbs_status.sh`

This script follows the status of jobs that have been submitted by `pbs_submit.py` by running `qstat` and filtering the output to determine the status of the job of interest.
The result is reported back to Snakemake as either "running", "success" or "failed".
Snakemake then makes decisions such as to whether to wait, restart the job or submit follow up jobs according to this report.

This script is specified for the `cluster-status` option in `config.yaml` above. 
Snakemake reads the config file and runs this script to check on the status of submitted jobs every 10 seconds (not configurable).

As well as reporting back to Snakemake, this script also records its observations in `logs/status_errors.log`, which can be used to debug problems with the interface between Snakemake and PBS Pro.

This script can be ported to other workflows without modification.
